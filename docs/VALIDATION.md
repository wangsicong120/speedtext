## 排序与自动选择回归

保留 3.2 引入的“检测全部 / 检测筛选结果”完成后的速度排序与自动选择，本轮将两种视图统一为单列表：

- 排序分层：完整采样（`ok`）优先；小文件（`small`）随后；失败、超时、取消和未检测项最后。同一层级内按实测 MiB/s 从大到小排列，速度相同保持原顺序。
- 自动选择：完整检测结束后选择最快的 `ok` 节点作为测速地址；没有 `ok` 时回退到最快的 `small` 节点；两者都没有时不切换。
- 取消保护：停止检测、关闭配置弹窗、导航中断或检测未完整结束时，不自动切换地址。单条节点的“检测”按钮只更新该条结果，不触发自动排序和切换。
- 视图：完成后自动进入“实测速度排序”，可点“恢复默认顺序”回到原顺序；两种视图均不分组，排序视图遵守当前搜索过滤，不把未匹配节点混入结果。速度排序按 URL 去重，默认顺序保留原有重复记录。
- 小文件速度只作可读性参考。即使小文件算出的瞬时速度更高，也不会排在完整采样之前，避免把不可靠样本当作真实带宽。

回归证据：

- `tests/unit/probe.test.js` 的 3 组用例继续覆盖分层排序、最快节点回退和同速稳定性；`fastestProbeItem` 不会选择失败/超时项。
- E2E `batch sampling ranks by measured speed and selects the fastest only after completion`：用 3 个本地受控流（fast、medium 均超过 64 KiB，tiny 为小文件）验证检测完成后顺序为 fast → medium → tiny，当前地址和下载输入框自动切到 fast，排序按钮进入按下状态；点击“恢复默认顺序”后回到添加顺序 medium → tiny → fast，且无分组。
- 同一 E2E 随后手动选回 tiny，再启动一次检测并在进行中点击“停止检测”，确认地址仍为 tiny，且提示“未自动切换测速地址”。测试不依赖第三方节点，也不产生真实大流量下载。

## 覆盖的关键行为

- 下载：HTTPS/域名/凭据校验、签名查询参数保留、先验证首块再扩展并发、流量/时长停止、连接及流式读取超时、有限 HTTP/CORS 重试。
- 默认设置：流量上限与自动停止独立开关，默认关闭、有效值均为 `0`；不自动下载，不限量开始前仍需确认。显式开关可保存，旧版隐式 `100 MiB / 60 秒` 不重新启用。
- 取消：停止所有连接、取消读取和退避，旧会话不能污染新统计；离线停止，联网后不自动启动。
- 节点：指定地址精确删除、单列表、公司名称及旧配置一次性迁移；自定义文本不执行 HTML，名称/URL 搜索、重复 URL 隐藏、撤销、损坏/被拒绝的存储回退。
- 节点恢复：首次默认使用剩余列表首项，保留未被删除的保存选择；旧被删选择一次性重置并提示，失败后可手动切换默认节点或进入检测，不增加后端下载代理。
- 采样：URL 去重、4 并发上限、读取预算、关闭弹窗即取消、重新采样不接收旧结果、手动复制回退；完整结束后按速度排序并自动选择，取消不切换。
- 交互：失焦校验不再移走鼠标下方的开始按钮，错误聚焦到相关字段；主题持久化、键盘跳转、弹窗焦点、Escape、伪熄屏、统计导出脱敏。
- 自动网络检测：每轮完成后约 30 秒刷新，关闭偏好持久化；并发刷新共享一轮，后台/离线/离开页面取消，恢复时刷新，迟到响应不能覆盖新生命周期结果。
- IP 与静态回退：优先本站边缘；静态 HTML、404、CORS 或限流时回退到明确标注的第三方 IP，同源图标测本站首响应；IP 格式校验、响应体读取上限、API/ipinfo 五分钟冷却及非滑动截止时间。
- 后端：只读方法、HEAD、同源检查、无代理出口、查询参数拒绝、安全头、真实静态文件、未知路径与测试流路径 404、本地伪造转发头无效。

### 原生浏览器 API 回归

3.1 起实际页面复现了类成员直接调用原生 `Window.fetch`、`setTimeout` / `clearTimeout` 的 `Illegal invocation`：下载被误报为 CORS/网络不可达，连通性失败，自动刷新中断。相关修复与本轮代码共存，`tests/e2e/native-api.spec.js` 的两个场景在 3.2 的两个项目中继续通过：

- 不替换 `window.fetch`、不安装 `page.clock`，用本地构造的 HTTP 响应验证一次可读的 64 KiB 下载及限额停止。
- 使用真实 30 秒定时器等待第二轮检测完成，再验证关闭自动刷新后的手动刷新；无页面错误、不触发下载。

单元测试另检查注入的 fetch 与定时器不会收到类实例作为 `this`。常规界面测试仍使用固定小响应，不把模拟 API 的成功当作原生 API 的证明。

### 测试不产生大规模真实下载

下载/采样使用显式启用的本地模拟流。第三方响应由本地构造；CORS 和 opaque 响应测试通过 Chromium CDP 提供 HTTP 响应，保留浏览器自身安全判断，避免 Playwright `route.fulfill` 自动补 CORS 头或取消 `favicon.ico` 造成假阳性。

没有关闭 CORS、证书校验或浏览器安全功能。自动化验证证明逻辑和交互行为，不证明历史第三方节点当前可用、峰值带宽或免流。下方单独记录的一次真实下载也不是批量节点可用性测试。
